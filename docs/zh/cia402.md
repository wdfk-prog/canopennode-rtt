# CiA 402 Device 诊断与产品集成

本文说明可选的每轴诊断路径，以及 package demo Object Dictionary 与产品生成式 CiA 402 Object Dictionary 之间的边界。PDS supervisor 见 [CiA 402 Pure-C Device Core](cia402-device-core.md)，RT-Thread lifecycle 接入见 [CiA 402 RT-Thread Device 集成](cia402-device-rtt.md)。

![CiA 402 EMCY 诊断流](../assets/cia402-emcy-diagnostic-flow.svg)

## 诊断模型

每个 logical device 独立维护 fault latch，并对应自己的标准 Error-code 对象，例如 `0x603F`、`0x683F`、`0x703F`。产品通过 `CO_402_device_diag_if_t` 提供故障映射，Device core 不自行定义产品错误分类。

映射中的 PDS Error-code、CANopen EMCY code 和 manufacturer information 相互独立。启用 `PKG_CANOPENNODE_CIA402_DEVICE_DIAGNOSTICS` 后，Device core：

- 在某个 axis 首次进入 active fault 时锁存故障；
- 更新该 axis 的 Error-code 对象；
- 为新的故障生成一个 pending diagnostic event；
- 同一故障保持锁存期间不重复生成事件；
- CiA 402 Fault Reset 成功后只清除对应 axis。

故障编码仍由产品应用负责。Package 不替产品定义电机、逆变器、传感器或功率级的错误码。

## RT-Thread EMCY bridge

`PKG_CANOPENNODE_CIA402_DEVICE_RTT_EMCY_BRIDGE` 把 pending axis diagnostic 接到 CANopenNode EMCY。桥接层使用 CANopenNode manufacturer-specific error-bit 区间，并以 `0x40 + logicalDevice` 表示 axis source，因此 logical device 0、1、2 分别使用 `0x40`、`0x41`、`0x42`。

桥接层只在 OD lock 已释放、但 lifecycle mutex 仍保护当前 `CO_t` 时调用 `CO_errorReport()` / `CO_errorReset()`。因此 EMCY 处理不会进入 `co_rt` 的 SYNC/RPDO/TPDO fast path。

Communication Reset 会重新绑定生成 OD，恢复仍处于 active fault 的各 axis Error-code，并把当前诊断状态安排到新创建的 `CO_EM_t`。该过程不会重新执行 DriveIF power transition。CAN bus-off 仍属于 CANopen communication fault，不转换为 axis fault。

## Demo OD 与产品 OD

`examples/demo_device/` 是 package bring-up 使用的 Object Dictionary，其中包含生成式 CiA 402 对象和可选 manufacturer-specific demo 对象。它适合 package 集成和软件演示，但不代表产品 identity 定义。

产品固件通常应：

1. 维护自己的 XDD/EDS source of truth；
2. 从产品描述生成 `OD.c` 与 `OD.h`；
3. 设置 `PKG_CANOPENNODE_USING_DEMO_OD=n` 关闭 package demo OD；
4. 由 BSP/Application 构建系统加入产品生成 OD；
5. 在产品仓库内维护 identity、PDO 布局、支持的 mode、fault taxonomy 和持久化策略。

`examples/cia402_multi_axis_device/` 说明仓库内面向产品的多轴 OD 参考布局。其生成物应来自同一份一致的 device-description revision。

## 产品 identity 与生成物

以下版本概念应分开管理：

- XDD/EDS file version：设备描述版本；
- OD `0x1018:03`：产品/设备 revision；
- OD `0x100A`：固件 software version。

产品仓库可以用 manifest 记录 generator version、source revision、选定 CiA baseline、identity 和文件 hash。Manifest 只是生成物元数据，不能替代 XDD/EDS 作为语义 source of truth。

不要直接修改生成后的 `OD.c`/`OD.h` 来修复与 XDD 的不一致；应修改设备描述并重新生成。

## 集成边界

- Package Device core 负责 PDS supervisor 与 OD binding，不负责电机控制实现。
- RT-Thread adapter 负责 lifecycle attach、同步和 worker thread，不负责产品 fault policy。
- 产品负责生成 OD、identity、fault mapping、DriveIF、mode 实现和应用安全策略。
- Manufacturer-specific demo object 只是 package 辅助接口，不应成为设备识别的隐式依赖。
- CiA 402 conformity/certification 不属于本仓库文档的声明范围。
